--------------------------------------------------------------------------------
BACKEND REQUIREMENTS NOT YET IMPLEMENTED
--------------------------------------------------------------------------------

1. Per-customer registration status endpoint
   Currently isNSEConnected() (the NSE admin session token) is used as the
   registration indicator, which is consistent with the rest of the application.
   A dedicated endpoint is needed to fully decouple browsing from the admin token:

   GET /api/customer/nse-registration-status
   Response: { registered: boolean, clientCode: string | null }

   This endpoint must identify the customer from their authenticated Lendrix
   session. It must never accept a client code or customer ID from the browser
   as proof of ownership.

2. Client code retrieval by authenticated Lendrix customer
   The backend must associate the NSE client code with the Lendrix customer
   identity and return it only to that customer's authenticated session.
   The frontend must never invent, guess, or accept a client code from the
   browser.


--------------------------------------------------------------------------------
INVESTMENT FUNCTIONALITY REQUIRING SEPARATE BACKEND INTEGRATION
--------------------------------------------------------------------------------

The live investment flows (Invest Once, Start SIP, Start XSIP, Switch Fund)
use the existing NSEBuyFlow, NSESipFlow, NSEXsipFlow, and NSESwitchFlow
components. These submit orders to the NSE exchange via the backend proxy.

They work end-to-end only when:
- The NSE backend proxy is configured with valid member credentials
- The customer has a registered NSE client code
- The customer has a verified bank mandate (for SIP/XSIP)

A demo simulation path is available in NSEInvestmentFlow for testing without
live credentials. No live exchange orders are submitted in demo mode.


--------------------------------------------------------------------------------
CUSTOMER JOURNEY AFTER THESE CHANGES
--------------------------------------------------------------------------------

Customer opens Lendrix
  -> Lands on /mutual-funds (Mutual Funds dashboard)
  -> Browses schemes, searches, filters, paginates (no login required)
  -> Clicks "Start SIP" on a scheme
  -> If NOT registered: sees "Complete Your Investor Registration" dialog
       -> Clicks Cancel: returns to dashboard, scheme still visible
       -> Clicks Complete Registration: goes to /investor-registration
            -> Completes 5-step UCC registration form
            -> Clicks Back/Close: returns to /mutual-funds
            -> Original scheme and SIP action are automatically restored
            -> SIP flow opens directly
  -> If already registered: SIP flow opens directly, no prompt shown

Returning customer
  -> Opens /mutual-funds directly
  -> Browses schemes immediately
  -> Clicks investment action -> flow opens directly (already registered)
  -> Never sees NSE login page during this journey
